# QA道場 — 仕様から、品質を見抜く。

QAエンジニア向けの**実践型テストトレーニング**。問題の選択肢を答えるのではなく、仕様を読み、自分でテストを設計し、意図的に不具合が組み込まれた模擬アプリを実際に操作して、不具合報告まで行います。

## 公開先

https://k-yumoto-ist.github.io/qa-dojo/

> 初回はリポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選択してください。これが設定されていない場合、ワークフローのデプロイが失敗することがあります。

## 実装済みの演習

**Level 01: ECサイトの注文フォーム**

1. **仕様理解:** 注文数量、送料、クーポン、メールアドレス、備考の期待仕様を確認。
2. **テスト設計:** 観点・前提・手順・期待結果を自分で記述して保存。
3. **実機検証:** 実際の注文フォームに入力し、計算結果や注文処理を確認。操作ログが残ります。
4. **不具合報告:** 観点、再現手順、期待結果、実際の結果を記載。事前に該当する挙動を観測している場合にルールベースで受理します。

採点は、登録したテスト観点（最大30点）、観測した意図的不具合（最大40点）、有効な不具合報告（最大30点）に基づく**定型ルール**です。文章の意味理解・AI評価はありません。実務的なテスト設計／報告の品質については、指導者によるレビューを想定しています。

## 技術構成

- HTML / CSS / Vanilla JavaScript（フレームワーク・ビルド不要）
- GitHub Pages（`main`へのpushでGitHub Actionsから自動デプロイ）
- ブラウザの localStorage に学習記録を保存
- AI・データベース・サーバー・ログイン機能なし

**データは利用中のブラウザ内だけに保存されます。** 別端末と同期しません。リセットすると消去されます。仕様や不具合の判定ルールはクライアント側コードに含まれるため、開発者ツールで答えを調べることもできます。公開演習環境として意図した制約です。

## ローカル起動

`index.html` をブラウザで開くか、HTTPサーバーで配信してください。

```sh
python3 -m http.server 8000
```

`http://localhost:8000` にアクセスします。
